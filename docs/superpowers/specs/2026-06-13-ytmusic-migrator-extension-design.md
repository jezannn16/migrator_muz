# Дизайн: браузерное расширение «Yandex Music → YouTube Music»

**Дата:** 2026-06-13
**Статус:** утверждён (brainstorming)
**Репозиторий:** https://github.com/jezannn16/migrator_muz (новый компонент `extension/`)

## Цель

Перенос музыки из Яндекс.Музыки в YouTube Music для **обычных пользователей** — без техничных шагов (никакого cURL/DevTools/вставки токенов). Простота входа сопоставима с Яндексом.

## Ключевые решения (из брейншторма)

| Вопрос | Решение |
|---|---|
| Вход в YouTube | Браузерное расширение, авто-захват живой сессии (cookies API), **без вставки** |
| Где крутится миграция | Полностью в расширении (браузер юзера), не на сервере |
| Хранение токенов | Только локально (`chrome.storage.local`), на наш сервер ничего не уходит |
| Объём MVP | Лайки + плейлисты + альбомы |
| Стек | TypeScript, Manifest V3 |
| Браузеры | Chrome + Edge (Chromium) |
| Распространение | Сначала sideload + лендинг, затем Chrome Web Store |
| Backend | Нет (Go — кандидат на будущий микросервис: оплата/аналитика/релей, не MVP) |

## Архитектура

Тонкого сервера нет. Продукт = расширение Chrome/Edge (MV3) на TypeScript. Вся логика выполняется в браузере пользователя.

### Почему вход простой
- **YouTube:** расширение с `host_permissions` читает cookie сессии (`SAPISID` / `__Secure-3PAPISID`) через `chrome.cookies` API (возвращает и httpOnly), само вычисляет заголовок `SAPISIDHASH` (`<ts>_<SHA1(ts + " " + SAPISID + " " + origin)>`) и шлёт авторизованный `fetch` к `https://music.youtube.com/youtubei/v1/...` с `credentials:'include'` (cookie прикрепляет браузер). Пользователю достаточно **быть залогиненным в music.youtube.com** в этом браузере. Это повторяет browser-auth ytmusicapi, но без сохранения cookie и без DevTools.
- **Яндекс:** кнопка «Войти через Яндекс» открывает OAuth implicit-страницу (официальный client_id `23cabbbdc6cd418abb4b39c32c41195d`). После логина редирект содержит `#access_token=...`; контент-скрипт расширения на странице редиректа читает `location.hash`, извлекает токен, отдаёт фоновому скрипту. Один клик, без копирования. Токен — в `chrome.storage.local`.

### Компоненты

- **manifest.json (MV3)**
  - `host_permissions`: `https://music.youtube.com/*`, `https://api.music.yandex.net/*`, `https://oauth.yandex.ru/*`, `https://*.music.yandex.ru/*`
  - `permissions`: `cookies`, `storage`, `tabs`
  - service worker (фон) + страница UI
- **auth/yt.ts** — чтение cookie, расчёт `SAPISIDHASH` (SubtleCrypto SHA-1), фабрика авторизованного `fetch` к youtubei. Метод `isLoggedIn()` (есть ли валидная сессия).
- **auth/yandex.ts** — запуск OAuth-вкладки, перехват `access_token` контент-скриптом, сохранение/чтение токена, `isLoggedIn()`.
- **sources/likes.ts**, **sources/playlists.ts**, **sources/albums.ts** — выгрузка из `api.music.yandex.net` (Authorization: `OAuth <token>`). Нужны: account/status (uid), likes/tracks, playlists list + tracks, liked albums. Порядок: лайки по timestamp (старые→новые).
- **engine/match.ts** — порт логики из Python (доказана: 991/1012):
  - `normalize` (lowercase, убрать feat/скобки/пунктуацию)
  - `scoreCandidate` = 0.45·название + 0.35·артист + 0.20·длительность(±15с)
  - similarity-функция (аналог difflib ratio — Ratcliff/Obershelp или эквивалент)
  - `bestMatch` (порог, ранний выход при ≥0.85)
- **engine/migrate.ts** — оркестрация: создать целевой плейлист (с ретраем), искать, добавлять (`add_playlist_items` аналог, `duplicates=false`), resumable-стейт, отчёт misses. Ретрай транзиентных 400.
- **yt/api.ts** — обёртки youtubei: `search(songs)`, `createPlaylist`, `addPlaylistItems`, `rateSong` (опц.). Парсинг ответов youtubei.
- **ui/** — полностраничная вкладка расширения: выбор источников (лайки/плейлисты/альбомы), настройки (строгость, имена), прогресс-бар, счётчики, лог, таблица misses, кнопки старт/стоп, ссылки на созданные плейлисты.

### Где выполняется миграция

В **открытой UI-вкладке расширения**, НЕ в service worker (MV3 убивает SW через ~30с–5мин — длинный прогон на 1000+ треков погибнет). Страница расширения с `host_permissions` делает авторизованные cross-origin `fetch` к youtubei и Яндексу. Пользователь держит вкладку открытой (как сейчас в веб-версии). Стейт — в `chrome.storage.local` по каждому источнику; обрыв/закрытие → продолжит с места, дублей нет.

### Объём

Три источника, каждый отдельным модулем:
- Лайки → плейлист «Yandex Likes»
- Каждый пользовательский плейлист → одноимённый плейлист в YT
- Лайкнутые альбомы → плейлист «Yandex Albums» (или по треку альбома)

Порядок добавления сохраняется (плейлист хранит порядок вставки).

## Обработка ошибок

- Транзиентные `HTTP 400 / Sorry, something went wrong` от youtubei → ретрай (3 попытки, бэкофф) — на create/add (как в Python-версии).
- Не найденные треки (score < порога) → список misses в UI + экспорт.
- Истёкшая cookie/токен YT или Яндекса → понятное сообщение «перелогинься», без падения прогона.
- Rate-limit → пауза между запросами (настраиваемая).

## Тестирование (TDD)

- Чистый TS: `normalize`, `scoreCandidate`, `bestMatch`, парсинг ответов Яндекса/youtubei, стейт/resume — юнит-тесты на фейках (как в Python: `tests/test_core_pure`, `test_migration`). Раннер: vitest или jest.
- Цикл миграции — на фейковых API-клиентах (инъекция), проверяем порядок, miss, resume, ретрай.
- Авторизация (cookies + SAPISIDHASH + Yandex OAuth) — **не юнит-тест**, отдельный ручной спайк в реальном браузере.

## Риски

- **Service worker MV3** — обходим запуском в UI-вкладке.
- **SAPISIDHASH / авторизованный youtubei-fetch из расширения** — load-bearing. **Спайк = гейт №1**: если из расширения не проходит — архитектура меняется.
- **Официальный client_id Яндекса** — грей-зона (как в текущей версии).
- **Chrome Web Store review** — может отклонить за автоматизацию/скрапинг YouTube. Отложено (sideload сначала).
- **ToS неофициальных API (Яндекс + youtubei)** — врождённый риск; для коммерции оценить отдельно.
- **Дублирование логики** — Python-движок не переиспользуется, матчинг переписывается на TS. Python-инструмент остаётся как личный/CLI.

## Фазы сборки

1. **Спайк авторизации (гейт всего проекта):** из MV3-расширения авторизованный `fetch` к youtubei (через cookies+SAPISIDHASH) реально проходит; Yandex OAuth-redirect-capture реально отдаёт токен. Проверка вручную в браузере.
2. Движок матчинга на TS + юнит-тесты.
3. Лайки end-to-end в UI-вкладке (создать плейлист, искать, добавлять, прогресс, resume).
4. Плейлисты + альбомы.
5. Лендинг + упаковка (sideload), затем заявка в Chrome Web Store.

## Что НЕ входит (YAGNI / позже)

- Обратный перенос (YT → Яндекс), другие сервисы (Spotify, Apple Music).
- Серверный backend, оплата, аналитика (Go-микросервис — кандидат на потом).
- Firefox/другие браузеры.
- Авто-обновление через стор (на этапе sideload — ручное).
