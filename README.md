# ymusic-migrator — перенос лайков Yandex Music → YouTube Music

Браузерный интерфейс с входом через **Яндекс** и **Google** (OAuth device flow). Переносит лайкнутые треки **в том же порядке**, в котором добавлял, с умным мэтчингом и возобновлением после обрыва.

Репозиторий: <https://github.com/jezannn16/migrator_muz>

## Запуск

Двойной клик по `start.bat` (поставит зависимости и откроет интерфейс), либо вручную:

```powershell
cd D:\мигратор
pip install -r requirements.txt
python app.py        # откроется http://127.0.0.1:5000 (только локально)
```

## Вход (всё в браузере)

### Шаг 1 — Яндекс
Кнопка **«Войти через Яндекс»** → на экране появится код → открой страницу подтверждения, введи код, разреши доступ. Токен прилетит сам. Регистрация приложения не нужна — используется device flow официального клиента.

*Запасной способ:* раскрой «Войти вручную» и вставь `access_token`.

### Шаг 2 — YouTube Music
Нужен **свой Google OAuth-клиент** (один раз, бесплатно):
1. <https://console.cloud.google.com/> → создать проект.
2. APIs & Services → Library → включить **YouTube Data API v3**.
3. OAuth consent screen → тип **External**, добавить себя в **Test users**.
4. Credentials → Create credentials → OAuth client ID → тип **TVs and Limited Input devices**.
5. Скопировать **Client ID** и **Client secret** в поля на странице → **«Войти через Google»** → ввести код на `google.com/device`.

*Запасной способ:* «Войти по заголовкам» — вставить Request Headers с `music.youtube.com` (F12 → Network → `/browse`).

### Шаг 3 — настройки и старт
Название плейлиста, приватность, строгость совпадения, доп. лайк → **▶ Старт**. Прогресс-бар, счётчики, живой лог, кнопка «Открыть плейлист», скачать `report.csv` / `misses.csv`.

## Как сделано

- **Порядок** — лайки тянутся с датой добавления, сортируются старые→новые, льются в плейлист (вставка хранит порядок точно).
- **Мэтчинг** — скоринг: название + исполнитель + **сверка длительности** (±15 с). Ниже порога → в `misses.csv`.
- **Возобновление** — прогресс в `state.json`; оборвалось → Старт снова, продолжит с места, дубли не плодит. Галка «Начать заново» — с нуля.

## Файлы

| Файл | Назначение |
|---|---|
| `app.py` | Flask-сервер (только localhost), роуты логина/миграции |
| `core.py` | движок: OAuth device flow, мэтчинг, порядок, стейт, отчёты |

Секреты (`yandex_token.json`, `oauth.json`, `yt_client.json`, `browser.json`) и данные прогона (`state.json`, `report.csv`, `misses.csv`) — в `.gitignore`, в репозиторий не попадают.

## Безопасность

- Сервер слушает только `127.0.0.1` — из сети недоступен.
- Токены лежат локально, в файлах под `.gitignore`. Не коммить их.

## Деплой на Render (личный, с паролем)

> Только для личного пользования. Состояние и токены глобальные (один пользователь). Для раздачи людям нужен мультиюзер-рефактор (см. дорожную карту).

1. <https://dashboard.render.com> → **New → Blueprint** → подключи репозиторий `migrator_muz`. Render подхватит `render.yaml`.
2. В переменных задай **`APP_PASSWORD`** — пароль на вход (Basic Auth).
3. **Apply** → дождись билда. Получишь URL вида `https://ymusic-migrator.onrender.com`.
4. Открой URL → браузер спросит логин/пароль (логин любой, пароль = `APP_PASSWORD`) → дальше как локально.

Ограничения free-плана:
- Диск **эфемерный** — после редеплоя/сна авторизация (`browser.json`, токены) стирается, нужен повторный вход.
- Сервис **засыпает через ~15 мин простоя**. Пока вкладка открыта и опрашивает статус — не спит. Закроешь во время длинной миграции — фоновый поток умрёт. Для 1000+ треков держи вкладку открытой или возьми платный план.
- `workers=1` обязателен (зашит в `render.yaml`/`Procfile`) — иначе глобальное состояние разорвётся.

Локально по-прежнему: `python app.py` (без `APP_PASSWORD` гейт выключен).

## Известные ограничения

- Мэтчинг по тексту не идеален — редкие/русскоязычные релизы чаще уходят в `misses.csv`. Понизь строгость и запусти снова.
- Если YT ругается на частоту запросов — подними `sleep` в `core.py` (`DEFAULTS`).
- Токен Яндекса/Google может «протухнуть» — повтори вход.
